# Пакет Arch Linux и CachyOS

`tools/package-arch` формирует архив исходников из содержимого проекта, вычисляет SHA-256, подставляет его в PKGBUILD и использует чистый образ Arch Linux x86_64. Базовый образ закреплён по дайджесту, пакеты среды сборки берутся из Arch Linux Archive за 15 ноября 2026 года. `makepkg` запускается через `chroot --userspec=nshbuild:nshbuild` в чистом корне контейнера без монтирования каталогов хоста. Cargo загружает зависимости согласно `Cargo.lock` на стадии `prepare`. Стадии сборки и проверки используют `--frozen`.

```sh
tools/package-arch
```

Инструмент требует Docker, GNU tar, zstd и pacman для локального чтения метаданных. Полученный PKGBUILD и соседний архив исходников можно передать в отдельный чистый Arch chroot с установленными зависимостями сборки и запустить в нём `makepkg --verifysource`, затем `makepkg --cleanbuild --noconfirm` от обычного пользователя. Команды `pacman -Qip`, `pacman -Qlp`, локальные проверки конфликта и SHA-256 сохраняются в `logs/arch-package-inspect.log`.

`tools/test-arch-package` проверяет установку, обновление, удаление, реальный `chsh` с PAM и откат в одноразовом контейнере Arch с отдельной локальной учётной записью. Контейнер запускается без сети и без примонтированных каталогов хоста. Передайте предыдущий пакет аргументом `tools/package-arch`, чтобы проверить обновление между фактическими версиями и отдельную чистую установку. Вызов без аргумента проверяет установку и удаление новой версии. Результаты записываются в `logs/arch-package-test.log`. Состояние и версия пакета для выпуска определяются итоговым отчётом проекта.

Для установки или обновления на целевой машине после согласования проверьте SHA-256 и содержимое конкретного файла, отсутствие конфликта по имени пакета и по пути `/usr/bin/nsh`. Для первой установки `tools/install-arch` принимает абсолютный путь к пакету и ожидаемую SHA-256, показывает команду установки и запрашивает подтверждение. Процедура изменения login shell описана в [LOGIN.md](LOGIN.md).
