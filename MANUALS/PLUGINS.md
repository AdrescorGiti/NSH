# Плагины NSH

Lua-плагины хранятся в `${XDG_CONFIG_HOME:-$HOME/.config}/nsh/plugins/`. Каждый каталог содержит `plugin.toml` и файл запуска. NSH загружает явно выбранные плагины и их объявленные зависимости. Права и владельцы проверяются на всём пути. Файлы плагина должны принадлежать текущему пользователю и запрещать запись группе и остальным. Символические ссылки в каталоге плагинов отклоняются.

## Подключение примеров

Скопируйте нужные каталоги из `examples/plugins/` или из `/usr/share/doc/nsh/examples/plugins/` в ваш каталог плагинов. Выполните `nsh plugin list`, чтобы увидеть их имена.

- `file-suggestions` показывает один серый суффикс для существующего пути. Right принимает суффикс. Lua выбирает кандидат и добавляет подходящее экранирование для пробелов и Unicode. Rust передаёт асинхронный снимок каталога и рисует текст.
- `syntax-colors` подсвечивает команды, аргументы, строки, переменные, пути и операторы. Палитра задаётся в начале `init.lua`. Проверка команд кешируется по каталогу и PATH на короткий срок.
- `custom-commands` добавляет `hello` и `cdev`. Вторая команда меняет каталог текущего сеанса на `$HOME/dev`.
- [`aurora-theme`](AURORA_THEME.md) задаёт двухстрочное приглашение и открывает меню команд по Tab. Цвета меняются в `plugin.toml`.

Добавьте команду включения в `conf.sh` или выполните её в интерактивном NSH.

~~~sh
nsh plugin enable file-suggestions
nsh plugin enable syntax-colors
nsh plugin enable custom-commands
hello user
~~~

В сеансе команда включения действует на его активный набор. В `conf.sh` настройки плагинов участвуют в транзакции. После первого запуска применяются команды настройки, а затем подготавливаются и активируются плагины из файла. Для явного сохранения выбора на следующие запуски выполните внешнее `nsh plugin enable NAME` из другой оболочки, или `command nsh plugin enable NAME` из NSH. Внешнее `disable` меняет сохранённый выбор тем же способом. Файл `plugins/enabled` обновляется атомарно.

## Управление

| Команда | Операция |
|---|---|
| `nsh plugin list` | Показать обнаруженные и выбранные плагины. |
| `nsh plugin info NAME` | Показать метаданные, совместимость и возможности. |
| `nsh plugin enable NAME` | Включить. Зависимости включаются автоматически. |
| `nsh plugin disable NAME` | Отключить явный выбор. Зависимость активна, пока используется другим плагином. |
| `nsh plugin reload NAME` | Подготовить новую Lua-среду внутри сеанса, затем заменить старые регистрации. При ошибке старый плагин продолжает работать. |
| `nsh plugin doctor` | Проверить каталоги, манифесты и зависимости без запуска Lua. |

`command nsh` и абсолютный путь к бинарнику обращаются к исполняемому файлу. Внешняя команда `reload` сообщает, что ей нужен владеющий плагином сеанс. Обычные POSIX-скрипты идут через встроенный интерпретатор. Явный `--plugins` активирует сохранённый набор для скрипта. Для восстановления используйте `nsh --no-plugins`. Он пропускает сохранённые плагины и директивы их включения в startup. Режимы `--vanilla` и `--posix` также их пропускают.

## Манифест и приоритет

~~~toml
name = "demo"
version = "1.0.0"
api_version = 1
entry = "init.lua"
description = "Команды для текущего сеанса"
author = "Локальный пользователь"
dependencies = ["common@^1.0", "palette"]
capabilities = ["shell-state", "stdio"]
priority = 10
nsh_version = ">=0.2.1, <0.3.0"

[options]
greeting = "Привет"
~~~

Имя совпадает с именем каталога. Разрешены латинские буквы, цифры, дефис и подчёркивание. `entry` — относительный путь без родительских компонентов. Версия, API и манифесты зависимостей проверяются до инициализации. Вне зависимостей меньший приоритет загружается раньше. При выборе провайдера больший приоритет выигрывает, затем учитывается имя. Регистрации с одинаковым именем требуют явной замены с разрешением `override`. Специальная POSIX builtin может быть заменена только с `override` и `special-builtins`. Системная конфигурационная команда `nsh` зарезервирована.

Плагины — исполняемый пользовательский код. Разрешения определяют доступ к операциям NSH. Для недоверенного кода нужна отдельная изоляция ОС. Ошибка callback сообщает имя, файл и строку Lua, когда она доступна. Ограничения Lua помогают с циклом или исчерпанием памяти внутри VM. Ввод-вывод и внешние программы могут иметь собственные задержки и побочные эффекты.

Раздел `[options]` доступен плагину через `nsh.config.get`. Эта секция и `nsh.require` требуют NSH 0.2.1 или новее. После изменения параметров выполните `nsh plugin reload NAME` внутри сеанса.

Создание обработчиков, замена диапазонов строки и работа с историей описаны в [Lua API 1](PLUGIN_API.md). Для измерения используйте [сценарии производительности](PERFORMANCE.md).
