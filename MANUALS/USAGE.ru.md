# Использование NSH

[English](USAGE.md)

| Вызов | Поведение |
|---|---|
| `nsh` | Читает stdin. Интерактивность по умолчанию требует TTY на stdin и stderr. |
| `nsh -i` | Принудительный интерактивный режим. |
| `nsh -c 'команды' имя аргументы…` | Выполняет строку. Имя становится `$0`. |
| `nsh -s аргументы…` | Читает команды из stdin. Операнды становятся позиционными параметрами. |
| `nsh -n script.sh` | Разбирает синтаксис без исполнения. |
| `nsh -l` / `nsh --login` | Загружает файлы входа. То же для ведущего `-` в `argv[0]`. |
| `nsh --posix` | Отключает оформление и конфигурацию NSH. Интерактивный запуск учитывает POSIX-переменную `ENV` при совпадении реальных и эффективных UID/GID. |
| `nsh --vanilla` | Пропускает стартовые файлы. Интерактивная история остаётся в памяти. |
| `nsh --no-plugins` | Оставляет обычную конфигурацию сеанса и пропускает Lua-плагины. |
| `nsh --plugins -c 'команды'` | Явно загружает сохранённый набор Lua-плагинов для отдельного процесса. |

`--` завершает опции перед операндом. После строки `-c` именем `$0` может быть буквально `--`. Login загружает `/etc/profile`, затем `$HOME/.profile` при совпадающих идентификаторах. Далее обычная интерактивная сессия загружает профиль NSH и [конфигурацию](CONFIG.ru.md).

## Скрипты

- `nsh script.sh` исполняет файл через NSH. Для прямого запуска используйте `#!/usr/bin/env nsh` или абсолютный путь к NSH.
- При прямом запуске файла с `#!/bin/sh` ядро использует интерпретатор из shebang.
- Когда `execve` возвращает `ENOEXEC` для исполняемого текстового файла без shebang, NSH разбирает файл сама.

Внутри NSH имя `nsh` открывает встроенные настройки активного сеанса. Используйте `command nsh` или явный абсолютный путь, чтобы запустить отдельный процесс. [Проверка и смена login shell](LOGIN.ru.md).
